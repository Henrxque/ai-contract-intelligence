Analyze a PDF

POST/api/analyze

Multipart form data. file is required; mode is local (default) or openai. Limit: 10 MB, 40 pages and 120,000 extracted characters. 

curl -X POST http://127.0.0.1:8000/api/analyze \
  -F "file=@app/samples/northstar-services.pdf" \
  -F "mode=local"

Local rules: matches supported English and Portuguese labels followed by a colon on one line. Unrecognized wording can be missed. OpenAI: requires server configuration and transmits extracted text to the provider; choosing this mode explicitly requests that transmission.

Try a synthetic sample

POST/api/demo

JSON body with sample: review, complete or invalid. Uses the same PDF reader, local extractor and validation pipeline as uploads. 

curl -X POST http://127.0.0.1:8000/api/demo \
  -H "Content-Type: application/json" \
  -d '{"sample":"review"}'

GET /api/samples/{sample} downloads the corresponding fictional PDF.

Export an analysis

POST/api/export/{format}

Pass the full analysis JSON as the request body. Available formats: json, csv, xlsx. Response is a downloadable attachment. 

curl -X POST http://127.0.0.1:8000/api/export/xlsx \
  -H "Content-Type: application/json" \
  --data-binary @analysis.json -o analysis.xlsx

Exports preserve field statuses, issues and evidence. Excel includes separate sheets for fields, findings and extraction metadata. This endpoint transforms the submitted data; it does not certify it or retrieve a saved result.

Understand field states

supported
Format checks passed, evidence quotes match their claimed pages, and the value matches a quote. This is not a guarantee of semantic correctness.
missing
No explicit value extracted. Required gaps block passing checks; optional gaps remain in findings and exports.
uncertain
Ambiguous wording, conflicting candidates, or evidence that cannot support the claimed value.
invalid
A value failed a deterministic check, such as a negative amount, impossible date, or end date before the start.

Durable batch processing and lineage

Open the pipeline workspace or use these endpoints:

POST /api/pipeline/demo persists the three fictional demo contracts. Repeating the request reuses matching successful runs.

POST /api/pipeline/batches accepts multipart files, mode, persist_consent=true and, for OpenAI, provider_consent=true. Maximum ten files and 10 MB combined. It stores original PDFs, text, extraction and results in local SQLite.

GET /api/pipeline/summary reports persisted counts and recent runs. GET /api/pipeline/batches/{batch_id} returns item outcomes.

GET /api/pipeline/runs/{run_id}/lineage returns run configuration, attempts and raw staging. GET /api/pipeline/runs/{run_id}/result returns the committed analysis for review or export.

POST /api/pipeline/runs/{run_id}/retry explicitly retries failed or resumes queued/expired runs, bounded to three attempts. Active leases return in_progress; completed runs return cached outcomes.

GET /api/evaluation returns the measured local-rule development benchmark with per-field mismatches. It is not a live LLM accuracy report.

Actionable errors

Errors use a stable envelope. Raw contract data and provider error details are not echoed in validation responses. 

{
  "error": {
    "code": "ocr_required",
    "message": "No usable text layer was found. Scanned PDFs need OCR before upload."
  }
}

422 invalid/unreadable input · 413 size limit · 429 provider quota · 502 provider failure · 503 provider configuration · 504 provider timeout.

Health and boundaries

GET/api/health

Returns application status, configured AI availability and PDF limits. No secrets are returned.

This portfolio application binds to loopback by default. It has no accounts, OCR or legal reasoning. Individual review is transient; batch mode persists original PDFs and processing data in local SQLite. Uploaded files may be temporarily spooled by the multipart framework. Browser results are kept in memory until refresh. Add authentication, workload isolation, body limits at a reverse proxy and an explicit data policy before any public deployment.
